## 검증 환경과 한계

Chromium(`/usr/bin/chromium`)과 Playwright를 사용했습니다. 실행 환경 정책이 `file://` 및 로컬 HTTP 직접 탐색을 차단하므로, 원본 HTML의 CSS·JS·이미지를 동일 내용으로 인라인해 `set_content`로 렌더링했습니다. 단일 파일 미리보기는 `iframe srcdoc`에서 화면과 내부 페이지 라우팅을 확인했습니다.

따라서 이 결과는 **배포 서버에 업로드한 실제 URL 탐색이나 사용자 PC의 파일 더블클릭 실행을 직접 검증했다는 뜻이 아닙니다.** 원본 파일의 상대 경로·파일 존재·앵커는 별도 정적 검사로 확인했습니다.

실제 Windows Chrome·Edge, macOS Safari, iPhone·Android 실기기의 동작은 배포 전 UAT에서 최종 확인해야 합니다. 스크린리더 전체 검증이나 WCAG 적합성 인증을 수행하지 않았습니다.

외부 영상·공식 문서·로그인·Google Forms의 모든 목적지 상태와 최종 상담 전달을 전수 검사하지 않았습니다. `CONTENT-SOURCES.md`의 공식 공개 출처와 기존 HTML에서 링크를 옮겼으며, 운영 외부 서비스는 수정하지 않았습니다.

이메일 앱 실행(`mailto:`)은 사용자 환경에 따라 달라집니다. 이 환경에서 실제 메일 전송을 실행하지 않았고 상담 접수 서버·CRM·자동 발송 기능을 새로 구축하지 않았습니다. 복사 대체 동작과 TXT 저장을 함께 제공했습니다.
