# PLURA v7.1 — 공통 헤더·푸터 분리 + 라이선스별 기능

## 이번 전달본의 기준

- 사이트 기준: 사용자가 첨부한 `v7.1(5).zip`.
- 분리 방식의 참고: 사용자가 첨부한 `ko(1).zip`의 `p_header.html`, `p_footer.html`, `data-include-path` 방식.
- 추가 본문: 사용자가 첨부한 `license.html`의 본문·표·페이지 전용 스타일 그대로.
- 메뉴 추가 위치: **도입 안내 → 라이선스별 기능** 한 곳.

이전 답변의 전체 수정 ZIP을 기반으로 덧붙인 것이 아닙니다. 이번에 첨부한 `v7.1(5).zip`에서 다시 작업했습니다.

## 변경 범위

기존 27개 콘텐츠 페이지는 헤더·푸터를 공통 파일 호출로 바꾸었습니다. 각 페이지의 `<main>...</main>` 원문, 제목·설명 메타데이터, 모든 인라인 스타일은 원본과 동일합니다. `license.html`도 첨부 본문을 그대로 사용합니다.

공통 헤더에만 라이선스 메뉴를 추가했습니다. **기존 메인 본문, 도입 안내 본문, 푸터에 라이선스 링크나 홍보 영역을 추가하지 않았습니다.** 첨부 `license.html` 자체의 기존 푸터에는 라이선스 링크가 있지만, 이번에는 사이트 원본의 공통 푸터를 적용하므로 그 링크도 공통 푸터에 옮기지 않았습니다.

기존 `res/`의 47개 파일(CSS·JS·이미지·다운로드)은 바이트까지 동일합니다. 기존 `site.js`도 수정하지 않았습니다. 추가한 스크립트는 `res/js/include.js` 한 개입니다. 네 개의 기존 KO 리다이렉트 파일도 수정하지 않았습니다.

분리를 위해 각 페이지의 헤더·푸터 마크업, 공통 스크립트 호출, 기존 호버 초기화의 대기 시점은 변경되었습니다. 따라서 기존 HTML 파일 전체가 바이트 단위로 같다는 뜻은 아닙니다. 위 구조 변경을 역변환하면 각 원본 HTML과 정확히 같아지는지 검증했습니다.

## 수정할 위치

| 수정 내용 | 수정 파일 |
|---|---|
| 상단 메뉴 추가·문구 변경 | `ko/p_header.html` |
| 공통 푸터의 회사 정보·링크 | `ko/p_footer.html` |
| 라이선스 표·본문 | `ko/license.html` |
| 다른 페이지 본문 | 해당 `ko/*.html` |

본문을 별도의 `p_body.html`로 옮기지 않습니다. 참고 ZIP처럼 본문은 `index.html`, `adoption.html` 등 각 페이지에 남아 있습니다. 페이지별 `<head>`도 각 HTML에 남겨 제목·메타데이터·전용 스타일을 유지했습니다.

### AI 페이지의 기존 차이 보존

이번 원본에서 `ai.html`의 헤더·푸터 일부 문구와 메뉴 항목이 나머지 페이지와 달랐습니다. 이를 임의로 통일하지 않았습니다. 두 공통 파일 끝의 `<template data-include-page="ai.html" ...>`가 AI 페이지에서만 기존 차이를 복원합니다. 라이선스가 들어가는 **도입 안내 메뉴는 이 예외 템플릿과 중복되지 않으며 공통 헤더 한 곳에만 있습니다.**

## 동작 방식

각 콘텐츠 페이지는 아래 형태의 슬롯을 사용합니다. 실제 파일에는 JavaScript 미사용 시의 작은 대체 링크도 포함되어 있습니다.

```html
<div class="site-header"
     data-include-path="./p_header.html"
     data-include-kind="header"
     data-nav-current="adoption.html"></div>

<main id="main">
  <!-- 해당 페이지의 기존 본문 -->
</main>

<div data-include-path="./p_footer.html"
     data-include-kind="footer"></div>
```

`include.js`가 같은 사이트의 두 HTML 파일을 읽은 뒤 슬롯 자체를 `<header>`와 `<footer>`로 교체합니다. 헤더 밖에 새 래퍼를 남기지 않아 기존 고정 헤더 동작을 유지합니다. 원본의 현재 메뉴 표시도 페이지별로 복원합니다.

두 공통 파일의 로딩이 끝나면 원본 `site.js`를 실행하고 기존 호버 초기화가 이어집니다. 이 순서로 모바일 메뉴·드롭다운·호버가 비동기 삽입된 헤더에 연결되도록 했습니다. 페이지별 기존 AI·ATT&CK 스크립트와 본문 기능은 그대로입니다.

일반 경로는 추가 외부 라이브러리, 빌드 도구, jQuery, PHP, Nginx SSI를 사용하지 않습니다. 두 공통 파일을 못 읽으면 본문을 지우거나 숨기지 않고 오류와 전체 메뉴 보기·새로고침을 표시합니다.

## 서버에 반영

압축 파일 안의 **`v7.1/` 폴더 전체**를 기존 배포 위치에 반영합니다. `ko/license.html`만 추가해서는 기존 페이지에 공통 메뉴 구조가 적용되지 않습니다. `p_header.html`, `p_footer.html`, `include.js`, 공통 호출로 변경된 콘텐츠 HTML을 함께 배포해야 합니다.

이미 `v7.1/` 경로 안에서 파일을 복사한다면 ZIP의 `v7.1/` **내용물**을 복사하여 `v7.1/v7.1/`로 중첩되지 않게 합니다.

공통 파일과 본문은 HTTP/HTTPS 주소로 확인합니다.

```text
/v7.1/ko/index.html
/v7.1/ko/license.html
```

`file://`로 HTML 파일을 더블클릭하는 방식은 공통 HTML을 불러오는 확인 방법으로 사용하지 않습니다. Python 3가 설치된 PC에서는 `v7.1/` 폴더에서 기존 미리보기 도구를 사용할 수 있습니다.

```powershell
python .\tools\preview.py --port 8761
```

위 로컬 미리보기 도구는 `v7.1/` 자체를 웹 루트로 사용하므로 화면 주소는 `http://127.0.0.1:8761/ko/index.html`, 라이선스 주소는 `http://127.0.0.1:8761/ko/license.html`입니다. 실제 사이트의 `/v7.1/` 접두 경로와 구분합니다.

JavaScript를 사용하지 않는 경우 각 페이지 본문은 남아 있고, 전체 메뉴·하단 메뉴를 직접 여는 대체 링크를 제공합니다. 공통 영역 자동 삽입과 동작형 메뉴에는 JavaScript가 필요합니다.

## 검증 자료와 범위

- `qa-shared-layout/source-preservation.json`: 원본 ZIP/첨부 라이선스의 SHA-256, 28개 본문 동일성, 구조 변경 역변환 검증, 기존 자산 47개 동일성.
- `qa-shared-layout/browser-checks.json`: Chromium 렌더링 및 메뉴·호버·탭·모바일 동작 검증. 정확한 테스트 방식과 환경 제한을 이 파일에 기록했습니다.
- `qa-shared-layout/http-checks.json`: 로컬 HTTP 서버의 각 실제 파일 응답·바이트 검증. 실제 서버 배포 결과가 아닙니다.
- `SHA256SUMS-shared-layout.txt`: 이번 전달본 전체 파일의 체크섬 목록.

이 실행 환경의 시스템 브라우저는 URL 탐색이 차단되어 있습니다. 설정을 우회하거나 변경하지 않았습니다. 화면·동작 검증은 허용된 `about:blank` 메모리 문서에서 수행했고, 공통 파일 응답과 `site.js` 로딩 경계는 실제 파일 내용으로 재현했습니다. 별도로 로컬 HTTP 요청으로 실제 파일 경로와 응답을 검증했습니다. **실제 HTTP 브라우저의 전체 네트워크 로딩, 운영 Nginx 설정, 운영 CSP·캐시 정책, 운영 서버 반영은 검증·수행하지 않았습니다.** 배포 후 PC·모바일에서 상단 메뉴를 통해 라이선스 페이지가 열리는지 최종 확인해야 합니다.

기존 `README.md`, `QA-REPORT.md`, `qa/`, `SHA256SUMS.txt`, `page-manifest.json`, 사이트 맵 등의 기존 자료는 원본 보존을 위해 수정하지 않았습니다. 이들은 이전 원본의 기록이며 이번 공통화 작업의 최신 검증 결과로 읽으면 안 됩니다. 이번 작업의 설명과 검증은 이 문서 및 `qa-shared-layout/`, `SHA256SUMS-shared-layout.txt`가 기준입니다.
