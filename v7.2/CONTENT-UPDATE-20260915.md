## 3. 전체 29개 페이지 공통 변경

상단 `PLURA-XDR` 메뉴에 `마이터 어택 기반 탐지`를 추가했습니다. `위협 대응` 메뉴의 `계정 탈취`는 `크리덴셜 스터핑`으로 명확히 표시하고, 보조 설명에 계정 탈취 방어를 남겼습니다. AI 메뉴 보조 설명과 푸터 대표 문구에도 AI 방어 메시지를 적용했습니다.

페이지 제목·설명·공유 메타정보, 로컬 페이지 목록과 manifest를 수정 내용에 맞게 갱신했습니다. 리소스 URL의 캐시 구분용 쿼리만 새 콘텐츠 빌드로 바꿨으며 CSS·JavaScript 파일 자체는 바꾸지 않았습니다.

## 4. 그대로 유지한 것

기존 A안의 화이트·블루 디자인, 화면 폭, 반응형 규칙, 최근 조정한 글자 크기, 이미지와 UI 동작을 유지했습니다. `site.css`, `pages.css`, `site.js`는 원본 ZIP과 SHA-256 및 바이트 단위로 일치합니다.

## 5. 적용 방법

전체 ZIP을 새 폴더에 압축 해제한 뒤 `v7.1/ko/index.html`을 확인하세요. 운영 반영은 기존 v7.1의 `ko/` 폴더 전체를 교체하면 됩니다. 공통 메뉴와 푸터도 수정했으므로 메인 파일 하나만 교체하지 마세요. 기존 `res/v7.1/`은 그대로 사용할 수 있으며 전체 ZIP에도 같은 파일이 들어 있습니다.

최상단 `index.html`은 로컬 시작용입니다. 운영 홈페이지 루트의 언어 선택 파일을 덮어쓰지 마세요. `previews/`, `qa/`, 검토 문서는 운영에 올릴 필요가 없습니다. 서버 배포·Nginx 설정 변경·검색 색인 공개는 이번에 수행하지 않았습니다.

## 6. 확인 결과와 미리보기

29개 콘텐츠 페이지를 320·390·768·1024·1440px의 다섯 폭에서 렌더링했습니다. 전체 가로 넘침과 점검 대상 제목·카드 넘침은 없었습니다. 로컬 링크·앵커, 메인 탭과 키보드 이동, PC·모바일 메뉴, FAQ를 점검했습니다.

환경의 브라우저 탐색 제한으로 페이지 이동을 통한 HTTP 통합시험 대신, 원본 CSS·JavaScript·이미지를 임시 인라인으로 주입한 Chromium 렌더링과 로컬 파일 경로 정적 점검을 사용했습니다. 운영 브라우저·서버 배포 시험을 대체하지 않습니다. 외부 웹폰트 요청은 제외하고 설치된 Noto Sans CJK KR 폰트로 점검했으므로 사용자 PC의 줄바꿈은 다를 수 있습니다. 배포 파일은 인라인으로 바꾸지 않았습니다.
