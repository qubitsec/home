CASE 01 / ZERO-DAY적용 시나리오

적용 상황

A 기업은 공개되지 않았거나 패치가 준비되기 전의 취약점을 악용하는 공격에 대비해야 합니다. 공격자는 웹 요청과 API, 서버 실행 경로를 바꾸어 가며 시험하고, 비정상 요청·오류 응답·파일 생성·외부 통신은 서로 다른 로그에 남을 수 있습니다.

PLATINUM 전용AI 연동 기반 제로데이 공격 대응 및 데이터 분석은 PLATINUM에서 제공합니다.라이선스별 기능

확인할 로그

웹 요청·응답본문, 헤더, 쿠키, URL과 비정상 응답
서버·PC 행위프로세스 실행, 파일 생성, 외부 연결
계정·시간 정보로그인 행위와 전후 이벤트의 연결

대응 방법

  1. 01

    AI로 공격 정황 분석

    AI 연동으로 웹·호스트의 원천 로그를 함께 분석해, 알려지지 않은 공격이나 우회·변형 시도의 맥락을 확인합니다.

  2. 02

    웹과 호스트 대응 연계

    검토된 공격 근거를 WAF 차단·가상패치와 EDR 행위 추적·격리에 연결합니다.

  3. 03

    증거와 조치 이력 관리

    SIEM 상관분석과 관제 검토로 공격 흐름을 정리하고, 사전에 정한 정책·승인 범위에서 조치합니다.

대응의 핵심

패치 이전에도 수집된 공격 징후를 분석하고, 확인된 근거를 차단·격리와 후속 조사로 연결합니다.

01

인증서버의 웹·계정 공격 대응

웹 요청은 WAF로 보호하고, 로그인 시도·인증 결과는 SIEM으로 함께 분석합니다. 크리덴셜 스터핑과 SQL 인젝션 정황을 연결해 차단 근거를 확인합니다.

02

단지서버의 웹셸·행위 확인

지원 운영체제의 단지서버에 EDR을 설치해 프로세스 실행, 파일 생성·변경과 외부 연결을 수집합니다. 웹 요청 이후의 서버 침해 흔적을 추적합니다.

03

월패드의 허용 범위 축소

월패드의 외부 직접 접근을 막고 허용된 단지서버 경로만 사용하도록 구성합니다. 불필요한 포트·서비스와 임의 앱 설치는 제조사·운영 정책으로 제한합니다.

04

지속 가능한 보안 운영

웹·인증·호스트 로그를 연결해 분석하고 필요한 차단과 후속 확인을 수행합니다. 클라우드 SECaaS와 전문 관제를 연계하는 운영 방식을 검토합니다.

도입 전 확인

외부에 노출된 인증·관리 서비스, 단지서버의 운영체제, 월패드 접근 경로와 로그 수집 가능 범위를 먼저 확인합니다.

WAF는 Reverse Proxy 방식의 HTTP/HTTPS 구간에, EDR은 지원 운영체제의 서버에 적용하는 구성입니다. 월패드 자체에 EDR을 설치하거나 모든 단말 통신을 WAF로 검사한다는 의미는 아닙니다.

대응의 핵심

인증을 지키고, 서버 내부를 확인하며, 월패드의 접근 경로를 제한합니다. 그 근거를 하나의 보안 운영 흐름으로 연결합니다.

전자신문 기고와 관련 블로그를 바탕으로 정리한 v6 적용 시나리오입니다. 특정 아파트의 구축 실적이나 검증된 차단 성과를 나타내지 않습니다.
