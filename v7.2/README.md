## 배포 방법 — 반드시 확인

1. 서버의 현재 v7.1을 별도 위치에 백업합니다.
2. 이번 ZIP의 **`v7.1/ko/` 전체**를 반영합니다. 메뉴·푸터가 모든 콘텐츠 HTML에 들어 있으므로 한두 페이지 교체로는 끝나지 않습니다.
3. 파일 덮어쓰기를 사용했다면 서버의 **`v7.1/ko/validation.html`을 별도로 삭제**합니다. 압축 파일에 없다는 것만으로 서버 파일이 삭제되지는 않습니다.
4. 사용 중인 XML 사이트맵에 이번 `sitemap-v7.1.xml`을 반영합니다. 다른 위치의 사이트맵을 운영한다면 그 파일에서도 삭제된 URL을 제거합니다.
5. `res/`는 이번 입력과 바이트 동일하므로 교체할 필요가 없습니다. 새 폴더에 통째로 배포하는 경우에는 ZIP의 `ko/`와 `res/`를 함께 사용합니다.
6. HTML/CDN 캐시를 사용하는 경우 갱신하고 실제 PC·모바일 메뉴와 고객 사례 연결을 확인합니다.

**도메인 최상위 언어 선택용 `index.html`은 덮어쓰지 마세요.** ZIP 루트의 `index.html`은 로컬 검토용 시작 파일이며 기존 바이트를 유지했습니다. `site-map.html`, `page-manifest.json`, `qa/`, `previews/`, `history/`, `tools/`, Markdown 문서는 검토 자료입니다. 공개 배포 대상에 넣을 필요가 없습니다.

이번 패키지는 서버의 Nginx·리디렉션 정책·검색 노출 정책을 변경하지 않습니다. 삭제된 주소에 대한 서버 측 이동 규칙이 필요하다면 별도 설정 대상입니다. `casestudy.html`의 기존 HTML 이동만 고객 사례로 고쳤습니다.
