## 1. 먼저 확인할 파일

`ko/index.html`은 메인, `ko/zta.html`은 제로트러스트 상세 페이지입니다. 전체 ZIP을 새 폴더에 해제하여 확인하세요. Python이 설치된 환경에서는 기존 `tools/preview.py`를 실행하여 로컬 미리보기를 열 수도 있습니다.

최신 캡처는 `previews/zerotrust-20260915/`에 있습니다. `baseline-20260914/`, `content-20260915/`는 이전 상태의 참고 자료입니다.

## 2. 메인 콘텐츠 변경

기존 대표 메시지 **“AI 공격을 AI가 방어합니다.”**는 유지했습니다. 첫 화면 설명과 기술 태그에서 제로트러스트로 연결합니다.

기존 핵심 기술 카드 3개에 **제로트러스트 / 가시성·분석·대응**을 더해 4개로 구성했습니다. 카드 순서는 다음과 같습니다.

1. 마이터 어택 기반 탐지
2. 크리덴셜 스터핑 공격 대응
3. AI 공격을 AI로 방어
4. 제로트러스트 가시성·분석·대응

데스크톱에서는 4열, 중간 화면은 2열, 모바일은 1열입니다. 기존 카드의 제목·본문 폰트 크기를 줄이지 않았습니다.

핵심 기술 카드 바로 다음에 제로트러스트 전용 영역을 추가했습니다.

> **제로트러스트 7대 영역,**  
> **4개 영역을 하나로.**
>
> 네트워크·호스트의 가시성, SIEM의 상관분석,  
> SOAR의 정책 기반 대응으로 지속 검증을 지원합니다.

4 / 7 표시와 4개의 지원 기능 카드를 배치하고 상세 페이지와 연결했습니다.

## 3. “7개 중 4개”의 기술 기준

이번 홈페이지에서는 **미 DoD Zero Trust Strategy의 7대 필러**를 기준으로 사용했습니다. PLURA-XDR 공식 기능 설명과 사용자 요청에 근거한 홈페이지용 기능 매핑이며, 외부 인증기관의 판정이나 모든 세부 요건 충족 결과가 아닙니다.

| 대응 영역 | 홈페이지에 연결한 PLURA-XDR 기능 | 설명 범위 |
|---|---|---|
| 네트워크·환경 | WAF · 네트워크/보안 장비 로그 | 웹 요청·응답과 연결 로그의 가시성, 공격 분석, 정책 기반 웹 방어 |
| 기기·호스트 | EDR · VAS · Forensic | 서버·PC 행위와 보안 상태·변경 흔적 확인 |
| 가시성·분석 | SIEM · AI 상관분석 | 분산 로그·공격 흐름·탐지 근거 연결 |
| 자동화·오케스트레이션 | SOAR · 정책 기반 대응 | 허용된 차단·격리·알림과 실행 이력 연결 |

**SIEM을 독립적인 필러로 중복 계산하지 않았습니다.** SIEM은 가시성·분석, SOAR는 자동화·오케스트레이션에 연결했습니다. 사용자·애플리케이션/워크로드·데이터는 조직의 인증·접근·보호 정책과 함께 설계하는 영역으로 구분했습니다. 4개 영역의 전체 구현, 전체 네트워크 제어, 모든 접근제어/인증 대체, DoD 인증 또는 특정 성숙도 달성을 새로 주장하지 않았습니다.

메인은 짧은 설명, `zta.html`은 7개 필러 도식·4개 영역별 지원 기능·관측→분석→대응→개선 흐름·공식 자료 연결로 구성했습니다.

## 4. 상단의 기존 네 가지 요약 항목은 그대로 유지

사용자가 다시 짚은 문구는 삭제하거나 제로트러스트로 교체하지 않았습니다.

| 제목 | 설명 |
|---|---|
| 마이터 어택 탐지 | 행위 · 기법 · 증거 연결 |
| 크리덴셜 스터핑 | 로그인 분석 · 공격 차단 |
| AI 공격 · AI 방어 | AI 분석 · 정책 기반 대응 |
| 전문 보안관제 | 검토 · 대응 · 개선 |

해당 `.a-proof-strip` 영역만 글자·SVG 아이콘·설명 글자의 대비를 키웠습니다.

| 항목 | 기존 PC | 수정 PC | 기존 모바일(600px 이하) | 수정 모바일(600px 이하) |
|---|---:|---:|---:|---:|
| 제목 | 14px | **18px** | 12px | **16px** |
| 설명 | 12px | **15px** | 11px | **14px** |
| SVG 아이콘 | 23×23px | **30×30px** | 18×18px | **26×26px** |

설명 색상: `#7f8ba0` → **`#53647e`**. 제목/설명 간격은 2px → 5px입니다. 1100px 이하에서는 2열, 379px 이하에서는 1열로 배치해 작은 화면에서 억지로 축소하지 않도록 했습니다.

실제 수정 위치는 `res/v7.1/css/site.css` **맨 아래**의 `2026-09-15 / Zero Trust + readable proof strip` 블록입니다. 기존 상단의 `.a-proof-strip` 선언보다 구체적인 `.v71-home .a-proof-strip` 선택자로 적용합니다. 향후 크기를 조정할 때는 이 하단 블록을 수정하세요.

```css
.v71-home .a-proof-strip b { font-size:18px; }
.v71-home .a-proof-strip p { font-size:15px; color:#53647e; }
.v71-home .a-proof-strip .icon { width:30px; height:30px; }
```

모바일 크기는 같은 블록의 `@media(max-width:600px)`에 있습니다. 다른 영역의 기존 글자 크기 조정은 보존했습니다.

## 5. 수정 파일 범위

`ko/index.html`, `ko/zta.html`, `ko/platform_xdr.html`, `ko/trust.html`, `ko/platform_siem.html`, `ko/platform_soar.html`의 본문을 변경했습니다.

전체 29개 콘텐츠 페이지에서 상단 PLURA-XDR 메뉴와 푸터에 제로트러스트 링크를 추가했습니다. 콘텐츠 버전과 리소스 캐시 쿼리도 갱신했습니다. `page-manifest.json`, `site-map.html`을 함께 갱신했습니다.

`site.css`는 기존 원문 전체를 유지한 채 하단에 범위를 제한한 스타일을 추가했습니다. **`pages.css`, `site.js`, 기존 이미지와 4개 리디렉션 파일은 바이트 단위로 동일합니다.** 외부 라이브러리·API·추적 코드·폰트 파일을 추가하지 않았습니다.

## 6. 서버 적용

**이번에는 HTML뿐 아니라 CSS도 반드시 교체해야 합니다.** 이전 답변의 “ko 폴더만 교체”는 이번 빌드에 적용되지 않습니다.

```text
v7.1/
├─ ko/                      ← 전체 교체 (29개 콘텐츠 + 기존 리디렉션)
└─ res/v7.1/css/site.css     ← 반드시 함께 교체
```

`page-manifest.json`, `site-map.html`도 패키지에 포함한 최신 파일로 맞추면 됩니다. `res/v7.1/css/pages.css`, `res/v7.1/js/site.js`, 이미지 등 나머지 리소스는 기존과 같습니다. 전체 폴더를 교체하는 방식도 가능합니다.

확인 URL은 기존과 같은 `/v7.1/ko/index.html`, `/v7.1/ko/zta.html`입니다. 최상위 `index.html`은 로컬 시작용이므로 운영 홈페이지 루트의 언어 선택용 `index.html`을 덮어쓰지 마세요. `previews/`, `qa/`, 문서는 운영 업로드 필수 항목이 아닙니다. CSS 쿼리 버전을 갱신했으며, 반영 후 강력 새로고침으로 확인하세요.

Nginx 설정, 배포 경로, SELinux 설정, robots/noindex 상태는 이번 작업에서 변경하지 않았습니다.

## 7. 점검 결과와 제한

29개 콘텐츠 페이지를 모두 렌더링했습니다. 본문 변경 6개 페이지는 11개 화면 폭(320/375/390/600/768/1024/1100/1190/1280/1440/1920px), 나머지 23개는 5개 폭(320/390/768/1024/1440px)으로 **총 181회** 확인했습니다. 문서 가로 넘침·점검 대상의 가로 넘침/실제 클리핑·보이는 이미지 누락·JavaScript 예외는 검출되지 않았습니다.

메뉴·탭·키보드·새 앵커 관련 **17개 동작 점검 통과**. 로컬 HTTP 리소스 **79개가 200이며 파일 바이트와 일치**했습니다. 로컬 참조 1722건의 파일·앵커가 유효했습니다.

이 실행 환경은 Chromium의 URL 탐색이 제한되어, 브라우저 렌더링은 배포 파일의 CSS·JavaScript·이미지를 임시 문서에 인라인으로 넣어 수행했습니다. 로컬 HTTP 점검은 별도 Python 클라이언트로 수행했습니다. 두 점검은 실제 서버의 브라우저 통합시험을 대체하지 않습니다. 외부 Noto Sans KR 다운로드는 제외하고 설치된 한국어 대체 폰트로 렌더링했으므로 사용자 PC의 실제 웹폰트 줄바꿈은 달라질 수 있습니다. 배포 HTML은 인라인으로 변경하지 않았습니다. 실제 운영 서버 배포는 수행하지 않았습니다.
