## 1. 변경 내용

### 불필요한 페이지 제거

`ko/deployment.html`을 제거했습니다. 전체 콘텐츠 페이지의 GNB·푸터, 검토용 페이지 목록, 페이지 매니페스트와 XML 사이트맵에서도 해당 항목을 제거했습니다.

도입 안내 메뉴는 **운영 방식·도입 절차 / 통합 도입 상담** 두 항목입니다. `ai.html`의 데이터 처리 영역에서 삭제된 페이지로 이동하던 버튼은 제거했습니다. `trust.html`과 `platform_backup.html`의 관련 본문 링크는 이미 존재하는 `ai.html#data`로 연결하고 링크 문구를 ‘AI 데이터 처리 기준’으로 정리했습니다.

## 3. 서버 반영 방법 — 중요

**이번에는 HTML 한 개를 교체하는 작업이 아닙니다. `ko/`와 `res/`를 함께 교체해야 합니다.**

1. 현재 서버의 v7.1 폴더를 별도 위치에 백업합니다.
2. 새 ZIP을 빈 폴더에 압축 해제한 후 새 `v7.1/ko/`와 `v7.1/res/`를 한 세트로 배치합니다.
3. 단순 덮어쓰기를 사용했다면 이전 배포 페이지 파일과 이전 리소스 버전 폴더가 서버에 남아 있지 않은지 직접 확인합니다. 덮어쓰기는 파일을 삭제하지 않습니다.
4. 브라우저에서 새로고침하고 메뉴·대표 페이지·모바일 표시를 확인합니다. CDN이 있다면 HTML/CSS 캐시를 갱신합니다.

운영 대상은 **`v7.1/ko/` 및 `v7.1/res/`**입니다. 기존 v7.2 서버 경로의 전환·리디렉션·삭제는 이번 ZIP이 자동 수행하지 않습니다.

**ZIP 맨 위의 `index.html`은 로컬 검토용 시작 파일입니다. 도메인 최상위의 언어 선택용 `index.html`을 덮어쓰지 마세요.** `site-map.html`, `previews/`, `qa/`, `history/`, `tools/`, Markdown 문서는 검토 자료이므로 공개 배포할 필요가 없습니다.

기존 외부 웹폰트 연결, 외부 문서·로그인 주소, canonical과 noindex 설정은 이번 범위에서 변경하지 않았습니다. 기존 페이지의 검색 노출 정책은 별도로 결정하세요.

## 4. 검증 범위

- 콘텐츠 페이지 28개 전체: 320 / 390 / 768 / 1024 / 1440px, **140회** 렌더링
- 미리보기·추가 반응형 경계 검증까지 합계: **194회** 렌더링
- 검사한 내부 링크·리소스 참조: **1,642개**, 누락·잘못된 앵커 0건
- 실제 UI 동작 검증: **88개**, 모두 통과
- 별도 로컬 HTTP 클라이언트: 정상 페이지·리소스 **81개** 200 응답 및 파일 내용 일치, 삭제 경로 2개는 404 확인
- 공통 JS 및 각 페이지의 기존 내부 JS·스타일 내용 보존 확인

렌더링은 **오프라인 Chromium에 검토용으로만 리소스를 임시 인라인한 방식**입니다. 배포 파일은 정상적인 외부 CSS·JS 참조 방식입니다. 이 환경에서는 Chromium의 localhost HTTP 탐색이 `ERR_BLOCKED_BY_ADMINISTRATOR`로 제한되어, 경로 확인은 별도의 Python HTTP 클라이언트로 수행했습니다. 외부 웹폰트는 로드하지 않고 설치된 한국어 대체 글꼴로 확인했습니다.

**운영 서버 배포, 실제 서버에서의 브라우저 HTTP 통합시험, 외부 링크 전체 확인은 수행하지 않았습니다.** 상세 결과는 `QA-REPORT.md`와 `qa/`에 있습니다.
