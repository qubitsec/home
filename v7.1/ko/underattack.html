START WITH EVIDENCE

IP와 접속 횟수만으로는 보이지 않는 공격. 로그인 요청과 결과를 함께 봅니다.

크리덴셜 스터핑은 정상 로그인과 같은 경로를 사용합니다. PLURA의 전용 필터는 요청 헤더·본문의 계정 식별 정보, 응답 상태·크기와 반복·세션 패턴을 함께 분석합니다.

요청 헤더·본문의 계정 정보

도메인·경로·메서드와 로그인 속성을 설정하고, 계정 식별 정보·접속 IP·시도 시각을 확인합니다.

응답 결과와 성공·실패 조건

서비스에 맞는 응답 상태값·크기 등으로 인증 결과를 구분합니다. HTTP 상태값 하나를 로그인 성공으로 단정하지 않습니다.

시도 횟수·계정 수·세션 행위

설정 시간 내 반복 횟수와 사용 ID 수, 로그인 이후 정상 경로의 접근 패턴을 비교해 자동화 공격 징후를 찾습니다.

CONNECTED RESPONSE

전용 필터로 탐지하고,
검증된 정책으로 차단합니다.

01

서비스별 로그인 조건 설정

보호할 도메인·로그인 경로·메서드·계정 속성과 성공·실패 판단 조건을 정의합니다.

02

임계치·세션행위 탐지

시도 횟수·사용 ID 수·시간 조건을 분석합니다. 세션행위 필터는 로그인 이후의 경로와 설정된 탐지 시간·매칭 조건을 함께 확인합니다.

03

탐지 모드와 차단 모드 운영

로그만 수집하는 탐지 모드와 탐지 시 차단하는 모드를 선택합니다. 정상 로그인 영향을 확인하며 차단 정책을 적용합니다.

04

연관 활동 분석과 계정 보호

웹 로그와 계정·호스트 이벤트를 연결해 후속 활동을 확인하고, 허용된 대응·관제 절차에 따라 조치 결과를 남깁니다.

필터 조건과 차단 범위는 서비스의 인증 방식·로그 수집 구성·허용 정책에 맞춰 설정합니다. 수집 항목과 마스킹 정책은 별도로 검토하며, 비밀번호 원문 저장을 탐지의 전제로 삼지 않습니다.

계정을 자동 잠그거나 세션을 종료하나요?
계정 잠금·세션 종료 등의 조치는 실제 연동 가능 여부와 권한, 승인 정책에 따라 달라집니다. 모든 인증 시스템에서 자동 집행한다고 약속하지 않습니다.
이 페이지는 긴급 사고 신고 페이지인가요?
아닙니다. 계정 공격 대응을 설명하는 페이지입니다. 도입과 지원 요청은 통합 도입 상담 및 공식 고객지원 채널을 이용해 주세요.
